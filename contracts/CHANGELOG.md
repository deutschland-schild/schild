# Changelog of the Schild contracts

## v0.6 (2026-11-06, unreleased) - D72: the first gateway version has no labs features; D73: rule repositories

Not backwards compatible with v0.5 for the gateway; nothing is installed outside the test lab. The lab and relay contracts (signal, feedback, ack, submission, checkpoint, rule-bundle, withdrawal, stream, log-tree, peer-request, `config-lab`, the lab dashboard API) do not change. `make contracts-test`: 1937 vectors after D72, 2022 after D73, Go and Python agree.

**D75 to D78 (2026-11-10): the release 0.1.0-alpha.1.** Backwards compatible within v0.6: one optional config key, one more enum value. `make contracts-test`: 2029 vectors, Go and Python agree, no earlier vector changed.

- **Config (`config-schild`):** `dashboard.allowed_hosts` (D76): up to 32 unique host names without port, scheme or wildcard under which the dashboard may be opened besides `localhost`, IP addresses and the listen host. Go `config.Dashboard.AllowedHosts`. Vectors valid 072, 073, invalid 175 to 179.
- **Dashboard API (client-dashboard):** baseline reason `dashboard_settings_dropped` (D78). A request under a host name that is not allowed gets 403 as plain text before the API (D76); the session cookie is not `Secure` on loopback or when the browser loaded the dashboard over plain HTTP.
- **Store (no contract file):** `schild.db` has schema version 1 from 0.1.0-alpha.1 on and is upgraded forward only at the gateway's start, with a backup (D75).
- **CLI (no contract file):** `schild init`, `schild dashboard setup-code` (D78); test lab switches are ignored by release builds (D77).

**D103 (2026-11-22, draft): tasks of a group run to their end.** [cluster.md](cluster.md) section 5, class `jobs`: next to the record `<name>` (latest start or sign of life) the ids `<name>.period`, `<name>.done` and `<name>.i.<16 hex>` (with `expires`); the data of a record (`at`, `node`) and its checks are unchanged, so no vector and no code of `contract/cluster` changes. A task's name is at most 40 of `a-z`, `0-9`, `_`, `-`. A node of the build before runs a task by its interval and `<name>` alone; its record counts as a finished period for a node of this build.

**D103 (2026-11-22, draft): the counters and charts of a group.** Additive. Client dashboard and agent API: query parameter `node` (`all` or a node id) on `getMonitoringNow`, `queryMetricSeries`, `getTrafficBreakdown`, and on `getWebsiteKpis` and `getWebsiteRealtime` of the dashboard; `cluster` (schemas `ClusterScope`, `ClusterNode`, `ClusterPartialNode`) on `MonitoringNow`, `SeriesResult`, `TrafficBreakdown`, `WebsiteKpis`, `WebsiteRealtime`; fixture `getWebsiteKpis.group`. In a group these answers add up every node by default, where they showed the answering node before; distinct clients are the largest estimate of the nodes (`clients_at_least`). A single gateway answers as before. No config key, no vector change.

**D103 (2026-11-22, draft): a node that returns catches up on every single request the others still keep.** Mesh ([cluster.md](cluster.md) section 9), same Ask kind `requests`, not compatible between nodes of the earlier draft: the numbers of the requests a node served are kept in its request store and survive a restart, an answer comes from memory or from disk, `epoch` is the node id and the name of the store (stable over restarts), `first` is the lowest number no deleted segment can have taken, numbers have holes. Request store (no contract file): a record may carry its number after the trailer; segments written before read as before.

**D103 (2026-11-22, draft): a new group secret moves the nodes, with what they held.** No wire or vector change ([cluster.md](cluster.md) section 6, "A new secret"): a node whose `cluster.secret_file` names another group than its directory holds moves to that group at its start, keeps its key and carries over the records of every class but `members` as records of its own with the clocks they had. Before, it refused to start its node and the directory had to be deleted by hand, which lost every running block under seven days, lifts, erasures and the certificate records on that node.

## v0 (2026-10-26) - frozen

First frozen version (stage 1 gate of concept 23). Adversarial review before the freeze; every finding has golden vectors, and Go and Python agree on all of them (`make contracts-test`: 418 vectors).

SecLang subset (network rules can only protect):

- Catch-all check: every rule needs one specific line, judged against the new benign corpus [seclang-benign-corpus.json](seclang-benign-corpus.json). Before, only patterns matching the empty string were rejected; `@rx .`, `@rx ^/`, `@beginsWith /`, `@streq GET`, `@pm mozilla` and `@within abc` (which matches every empty value) passed and block every request in Coraza.
- Operator arguments may not start or end with a space (Coraza trims `"@rx  .*"` to `.*`), `@pm` phrases are separated by exactly one space (Coraza turns `a  b` into an empty phrase that matches everything), and `%{` is forbidden in operators (Coraza expands `%{REMOTE_ADDR}` and `%{REQUEST_HEADERS.host}` in `@streq`, `@contains`, `@beginsWith`, `@endsWith`, `@within` and numeric operators).
- No escaped quotes in arguments (Coraza's even/odd backslash rule differs from other parsers), no backslash and no comma in actions.
- No nested quantifiers or quantified alternation, at most 1000 counted repetitions in total per pattern.
- `&` counts and `t:length` only with numeric operators; `Referer` and `Origin` only with detection operators; more client and host headers forbidden (`X-Forwarded-Server`, `X-Client-IP`, `Via`, ...).
- Every valid vector compiles in Coraza v3.8.1 and does not fire on ordinary requests.

Signal and feedback (E4, concept 24):

- Covert-address rule `noLeak` for `action_sig`, `category`, `agent.family`, `target.software`, `match_shape.location`: no IPv4 (dotted or dashed), dashed IPv6, 7+ digit runs or 8+ hex runs. `action_sig` at most 64 characters, `agent.family` without dots, `asn` at most 2^24 - 1 (no IPv4 as integer), `waf_rules` strictly ascending.
- Forbidden keys are compared after ASCII-only normalisation (`clientIp`, `Client-IP`, `client.ip`), the list covers more address, host, contact and key names, and objects inside arrays are checked.
- Signal and feedback envelopes carry exactly one signature (one sender, one issuer).
- `schild.signal.sent.v1` may record the canonical request shape so `request_sig` can be recomputed locally.

Signatures and trust:

- The key id is binding (no trial verification); a public key may appear only once in a trust store and in `schild.yaml` / `lab.yaml` (otherwise one signature counts for two operators or issuers).
- Acks must be signed by the lab named in the payload. Ack rejection reasons include `test_key`.
- Replay window, client state persistence, bundle expiry and withdrawal semantics are spelled out (envelope.md, stream.md).

Dashboard APIs:

- Every operation has a `default` RFC 9457 problem response with a stable `code` and optional field `errors[]`; every list is cursor-paginated (allowlist and withdrawals were not); the SSE event stream takes the same filters as the list; no `format` keywords. A test enforces these conventions and that the lab API has no IP parameter or property.
